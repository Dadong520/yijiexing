# 宜捷行乘客 Android 静态复核

日期：2026-10-23。范围：`android/app/src/main/AndroidManifest.xml` 与 `android/app/src/main/java/cn/hbzjhs/passenger/` 当前源码。独立审查 agent 只读代码，未操作模拟器、未部署、未修改 Android 源码。此报告不能代替设备运行验收。

## 本轮问题与修复复核

| 问题 | 源码复核结果 |
|---|---|
| 登录/验证码迟到响应使已清除会话重新生效，旧 401 影响新会话 | `PassengerStore` 对异步成功、失败及回调核对 `sessionGeneration`；清访问码、退出与更新访问码更新代次，API 捕获访问码与会话快照。已落实 |
| 旧的自动同步覆盖新动作状态，旧同步失败改变新动作连接状态 | `stateEpoch` 在动作开始前递增；自动同步状态、失败与重试副作用均核对 epoch。已落实 |
| 请求标识只在内存中，响应丢失后重启重试可能重复添加反馈/附件 | `pendingVault` 使用 Android Keystore AES-GCM 持久化；签名包含账号、动作与 payload；发送前 `commit` 成功才允许请求，成功后清除。存储错误处于 `run` 捕获范围。已落实；服务端仍是支付入账与订单状态幂等性的最终约束 |
| 正忙时动作静默丢弃，表单关闭造成已保存误解 | `run` 正忙时明确显示本次未提交；主要提交按钮按 busy 禁用。已落实 |
| 续叫等待时修改备注调用错误接口 | 当前界面调用 `order.remark`，与后端允许 WAIT_CONTINUE 的契约一致。已落实 |
| 处理中状态显示英文，无终点费用被显示为 0，退款缺金额 | 已有 PROCESSING 中文映射；费用卡和云端展开明细均显示待定；`refundAmount` 显示模拟退款。已落实 |
| 原型两个途经点、报价截止与车牌强调缺失 | 当前源码包含两个顺序途经点、服务器 expiresAt 倒计时与车牌突出。无可信评分/距离没有编造 |

本轮复核未发现新增 P0/P1 阻断。仍需真实运行验证网络响应丢失后重启、账号切换与旧请求交错、双端取消/退款/续叫和重新选择司机；源码防护存在不等于这些运行场景已经通过。

## 权限与外部服务标识

- Manifest 仅声明 INTERNET；应用禁用备份和明文网络。投诉图片通过系统选择器，不声明整库读取权限。
- 访问码、会话及待重试请求标识使用 Android Keystore AES-GCM 存储。
- 首页/订单路线明确标为坐标连线示意，未接地图搜索、道路导航或自动定位；司机位置仅展示司机上报值和时间。
- 模拟验证码未发送真实短信；支付及退款明确模拟。正式电话中继未配置，不能从体验版直接联系司机。
- 无终点订单允许先建单，开始行程前仍需补目的地；这与旧原型司机打表流程有差异，不应宣称等价还原。

## 小项与交付边界

已通知 Android agent 将无终点路线卡“先出发，稍后确定目的地”改成“先叫车，稍后补充目的地”，避免与服务端开始行程前必须补终点的规则冲突。

静态复核不证明原乘客小程序功能完全还原。尚未找到独立乘客小程序源码；旧原型可见的线下议价乘客扫码、确认价格、价格异议、支付和售后流程，已向主任务报告并协调补齐。详见 `SOURCE_FUNCTION_AUDIT.md` 与 `REFERENCE_PROTOTYPE.md`。
