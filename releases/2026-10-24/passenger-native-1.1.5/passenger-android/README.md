# 宜捷行乘客原生 Android 体验版

此目录独立实现 Kotlin + Jetpack Compose 原生乘客 App，不修改司机 Android 工程。两端通过独立 Cloud Run 体验服务真实共享持久化订单；不是本机假数据页面，也不通过后台沙箱替代乘客操作。

- 包名：`cn.hbzjhs.dc.passenger.cloud`
- 版本：`1.1.4-experience` / versionCode 6
- Android 8.0（API 26）及以上
- 固定服务：`https://driver-demo-491829048305.us-west1.run.app`
- APK：`app/build/outputs/apk/debug/app-debug.apk`
- 此为开发签名的可安装体验包，不是应用市场生产发布版本。

## 安装与使用

1. 将 APK 传到 Android 手机，点击安装；如系统询问，请允许当前文件管理器安装此来源的应用。
2. 打开“宜捷行乘客”，点“连接设置”，粘贴单独提供的独立环境访问码并保存。访问码不在 APK、源码或文档中。
3. 体验账号为 `13800000101`、`13800000102`、`13800000103`。点“获取验证码”后自动填入体验验证码；**未发送真实短信**。
4. 阅读并勾选体验说明，登录后选择即时、预约或竞价用车。
5. 起终点可通过体验地标、常用地址、历史地址或手工 WGS84 坐标选择。默认宜昌地标仅为方便体验；请在使用其他城市时自行调整地点坐标。
6. 在另一台设备的司机 App 上线接单或报价。乘客端订单页每 5 秒前台同步；竞价需选司机并模拟预付。
7. 司机到达后，乘客向司机提供实际乘车手机号的末四位。本人体验账号分别为 `0101` / `0102` / `0103`；代叫使用所选乘车人的末四位。
8. 普通与预约订单结束后在乘客详情中模拟支付，完成后评价、投诉或申请模拟发票回执。
9. 后台停止轮询。云服务暂停或访问码失效时自动停止轮询；恢复服务后点“刷新”或“重试”。订单操作超时请先刷新，避免误认为没有提交。

## 明确的外部服务边界

- 支付、退款、发票是**模拟**，不会真实扣款、转账、开具税务发票或发送邮件；回执不可报销。
- 短信为体验验证码回显；未配置真实短信提供商。
- 地图是 WGS84 坐标连线示意，没有正式地图搜索、道路规划、路况或导航；司机位置仅展示司机端真实上报值。
- 独立管理后台已支持查看和回复已保存的投诉与反馈；乘客端会同步显示“已回复”状态和回复内容。实时人工客服、电话中继及后台推送尚未配置；前台轮询或手动刷新时读取回复，不承诺实时回复时限。
- 原乘客小程序源码是否找到、原后端功能覆盖差异，参见顶层源码审计报告。

## 安全与费用控制

- 访问码和会话分别使用 AndroidKeyStore AES-GCM 加密存储；禁止自动备份，不嵌入任何访问凭证。
- 只请求构建指定的固定 HTTPS origin，不接受运行时修改服务地址；禁用 HTTP 与重定向。
- 自动同步只在 Activity STARTED 时每 5 秒执行，后台停止；断网退避，暂停或访问码失效停止自动刷新。
- 订单动作包含按账号和操作摘要隔离的请求幂等键，经 AES-GCM 加密同步保存，超时或进程重启后的相同操作复用；费用与订单状态以云端返回为准。
- 无需后台定位或存储权限；投诉选图使用系统选择器，只读取用户选中的文件，压缩到 512 KB 以内。

## 构建与测试

Java 17、Android SDK 34、Gradle 8.7。此机器的 Documents 下曾出现 Gradle 文件哈希卡住，建议同步源码到临时目录构建，排除 `.gradle` 与 `build`，完成后复制 APK 和测试结果。

```sh
JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home ./gradlew --offline --no-daemon testDebugUnitTest assembleDebug
```

默认固定上述项目编号服务域名，可通过非秘密构建参数 `-PYIJ_CLOUD_ORIGIN=https://...` 指定另一个独立服务。参数只允许无端口、无路径的 HTTPS origin。不得将访问码、token、Google Cloud 密钥写入任何构建参数。

首页参考旧原型调整为青绿配色、路线示意与下方地点卡；由于旧原型版本较早，未机械套用旧版取消费用与时限。当前竞价10分钟有效期为独立体验策略。报价只提供服务端真实给出的姓名、车牌、车型与金额；未编造评分、完成单量或距离。

单元测试覆盖坐标合法性、乘客白名单身份、整数分金额精度、重要状态与模拟支付说明。双模拟器、反重力独立测试与复测由主任务保留单独证据。

## 线下议价体验

1. 司机在已支持配对码的新版司机 App 中创建线下议价订单，生成 5 分钟有效的一次配对码。
2. 乘客在首页选择“线下议价 · 输入司机配对码”，粘贴一次码或完整链接。外部扫码工具如支持打开 `yijiexing://negotiation?code=...`，可跳转本页；App 无内置相机扫码器。
3. 认领后核对司机、车牌、报价版本和金额。可对当前版本提出 2–500 字价格异议，等待原司机重新报价。
4. 模拟支付确认窗口固定展示刚确认的版本与金额。如果司机已更新报价或处于异议状态，旧窗口禁止支付；即使新报价尚未轮询到达，也会由后端校验版本和金额阻止误付。
5. 点击“确认此版本金额 · 模拟支付成功”后直接进入行程中。失败、处理中或取消支付不会开始行程。行程结束后的评价、投诉、附件和模拟回执使用现有共享流程。

配对码属于短期邀请凭证，只在输入页面内存暂存，不写入持久化表单或公开截图；动作幂等仅保存账号+payload的SHA256摘要与UUID，不保存配对码明文。任何请求失败包括401/403都保留原幂等键，只有明确成功才清除；账号资料未同步时禁止提交，不用会话token替代稳定账号标识。

## 请求重试回归证据

1.1.2 将所有乘客动作及投诉附件统一交给生产组件 `PendingRequestJournal.execute`：先保存操作身份，再发请求；只有明确成功才清除记录。HTTP 401/403 等鉴权错误和 503/超时不会否定之前可能已经提交的请求。存储保存失败会阻止请求发出；成功响应后的清除失败会保留内存及磁盘中的原编号。已有加密记录读取失败时阻止新动作，不把失败当作空记录。

新增 4 个共用生产组件的回归测试，覆盖不确定提交→401→403→存储重建→同账号更换会话重登，跨账号及操作隔离，保存/清除失败、损坏记录，以及旧 token 摘要记录迁移；使用注入的存储与传输故障，不另写一份请求编号实现。连同已有坐标/身份/金额/议价测试，共 12 项。

旧版在账号资料为空时曾可能用 token 生成摘要。升级会尝试用**仍可取得的当前 token**查找旧记录，迁移到稳定乘客 ID 后再发送，保持原请求编号。已经丢失的旧 token 无法反查其 SHA256 摘要；清除应用数据也会删除本机重试记录。遇到这种历史边界时应先刷新并核对云端结果，不能承诺恢复已经丢失的编号。

## 竞价费用文案修正

1.1.3 区分未选定司机时的“体验估价（参考）”与各司机提交的报价，说明选定后才按该司机报价模拟预付；选定后的费用标题为“选定司机报价”。云端费用查询中的参考车费也明确标为体验估价。此修正仅调整展示，不修改金额、订单状态、支付或退款规则。

新增 2 项生产展示函数的状态测试，覆盖未选择时估价 29.26 元与司机报价 36 元并存、选定后费用来源字段仍保留 DEMO_ESTIMATE 的兼容情况，以及取消/续叫状态。连同既有 12 项共 14 项测试。1.1.2 安装包及原验证报告归档于 `verification/1.1.2/`；旧 UI 缺陷截图和云端状态留在项目 `qa/final-extra-ui/`，不覆盖。

1.1.4 仅优化编号展示：详情标题使用中文订单类型与安全格式下单时间，完整订单编号通过“查看订单编号”展开并可复制；列表、投诉与模拟回执使用相同的中文编号入口。旧订单真实起终点和编号数据保持不变，不将英文测试地址伪造为中文地址。新增 2 项生产标题函数测试，覆盖正常时间显示与无效时间的安全降级。1.1.3 已通过的双端预付/退款流程证据仍按原 APK 版本保留，1.1.4 的新增界面回归另行归档。
