## 二、乘客端接口契约（`/api/passenger/*`）
1. **`POST /api/passenger/auth/login`**：
   - 请求新增可选 `inviteCode`（空字符串或未传时忽略；非空时去首尾空格转大写校验 `[PD][0-9A-F]{6}`，仅首次注册新乘客时绑定拉新并发放新人券）。
2. **`GET /api/passenger/state`（及 action 返回的合并 state）**：
   - `operations.pricing`：`{"city": "<当前城市ID>", "tariff": {startPrice, startMeters, unitPrice, unitMeters, returnAfterMeters, returnRate, nightStart, nightEnd, nightRate, freeWaitMinutes, waitPrice, lowSpeedKmh, emptyFee, freeCancelMinutes}, "serviceFee": <启用时分值否则0>}`
   - `operations.cityPricing`：`{"420500": {"tariff": {...}, "serviceFee": 0}, ...}`（按城市ID索引，供乘客端叫车页本地即时预估运价费+区域服务费）
   - `coupons`：`[{id, templateId, name, label, type, threshold, amount, status: "UNUSED"|"LOCKED"|"USED"|"EXPIRED", source, claimedAt, validFrom, expiresAt, orderId}]`
   - `couponCenter`：`[{id, name, label, description, type, threshold, amount, remaining, claimedCount, perUserLimit, validity, validDays, validEndAt}]`
   - `couponPoolFused`：`boolean`
   - `referral`：`{code, inviteCode, invited, count, completed, awarded, reward, maxRewarded, records: [{mobileMasked, phoneTail, createdAt, status, reward, completed}], rule: {enabled, trigger, tiered, points, tiers, cumulative, bonuses}}`
   - `invoices`：每条回执含 `id, orderId, title, titleSnapshot, amount, status ("SIMULATED_ISSUED"|"RED_FLUSHED"), redFlushedAt?, redFlushReason?, reissueStatus? ("PENDING"|"APPROVED"|"REJECTED"), reissuedAs?, reissueOf?, notice, createdAt`
   - `invoiceReissues`：乘客重开申请列表 `[{id, invoiceId, orderId, amount, oldTitle, newTitle, status, reason, decision?, newInvoiceId?, createdAt, decidedAt?}]`
   - `orders[i]`：含 `tripFare`（运价费，分）、`serviceFee`（区域服务费，分）、`couponId`、`couponAmount`（优惠抵扣，分）、`couponLabel`、`fare`（应付实付 = `tripFare + serviceFee - couponAmount`）、`estimatedFare`、`estimatedTripFare`、`fareSource`、`fareDetail`、`cancelFee`（`null` 或 `{amount, status: "UNPAID"|"PAID", responsible, createdAt?, paidAt?, source?}`）。
3. **`POST /api/passenger/action` 新增/扩展动作**：
   - `order.create`：可选传 `couponId`（字符串；不使用时不传或传 `null`）。若存在未结清 `cancelFee.status == "UNPAID"` 返回 409 `reason="PASSENGER_OUTSTANDING_CANCEL_FEE"`。
   - `order.payCancelFee`：`{"id": "<orderId>", "expectedAmount": <int cents>}` -> 结清待付空车费并入账司机钱包。
   - `coupon.claim`：`{"templateId": "<id>"}` -> 领券并冻结资金池；熔断或余额不足返回 409 `"当前营销余额不足，无法领取"`（`reason="COUPON_POOL_FUSED"`）。
   - `invoice.reissue.apply`：`{"invoiceId": "<SI...>", "reason": "<2-200字>", "type": "PERSONAL"|"COMPANY", "title": "<抬头>", "taxNumber": "<企业必填>", "email": "<选填>"}` -> 提交重开申请。
4. **`GET /api/passenger/orders/<id>/fees`**：
   - 返回 `{orderId, fare, tripFare, serviceFee, couponAmount, couponLabel, fareDetail, cancelFee, estimatedFare, paymentFee: 0, paid, paymentStatus, refundAmount, sandbox: true, policyLabel}`。

## 三、司机端接口契约（`/api/*`）
1. **`POST /api/auth/login`**：
   - 请求新增可选 `inviteCode`（空串忽略；首次注册司机账号时绑定拉新）。
2. **`GET /api/state`**：
   - `operations.company`：含 `splitAccountStatus`（`"SIGNED"` | `"UNSIGNED"` | `null`）。若司机已绑定公司且该公司 `splitAccountStatus != "SIGNED"`，司机 `driver.online({"online": true})` 及接单/抢单/报价均返回 403 `"所属出租车公司尚未完成分账账户绑卡开户（模拟签约），请联系后台开通后再上线接单"`（`reason="COMPANY_SPLIT_ACCOUNT_REQUIRED"`）；未绑定公司的司机不受影响。
   - `state.orders[i]`：共享订单 `fare` 投影为 `tripFare`（运价费），同时提供 `payableFare`（乘客实付）与 `passengerServiceFee`。
   - `profile.serviceScore`：`{value, score, level, entries: [{title, delta, scoreAfter, date}], records, levels: [{name, min, max}], notice}`。
   - `profile.referrals`：`{code, inviteCode, invited, count, completed, awarded, reward, maxRewarded, records: [{mobileMasked, phoneTail, createdAt, status, reward, completed}], rule}`。
3. **`GET /api/orders/<id>/fees`**：
   - `{orderId, fare: tripFare, income: driverAmount, paymentFee: tripPayFee, splitFee: tripSplitFee, mapServiceFee, serviceFee: 0, passengerServiceFee, splitMode: "FEEDBACK3_FORMULA", final, fareDetail, policyLabel, sandbox: true}`。

## 四、管理后台接口契约（`/api/local/admin/v2/*`）
1. **`state.operations` 暴露字段**：
   - 原有字段保持兼容，新增：`defaultTariff`、`tariffs`、`serviceFees`、`companySplitAccounts`、`companySplitLedger`、`couponPool`、`couponPoolEntries`、`couponPoolAlerts`、`couponTemplates`、`newUserCoupon`、`referralRules`、`referrals`、`serviceScoreRule`、`serviceScoreEntries`、`serviceScoreStats`、`invoiceReissues`、`invoiceIssuer`、`techFeeRows`、`orderSettlements`。
2. **`AdminQueries` 数据集**：
   - 原有 12 个数据集保持兼容（更新 `invoices` 支持 `RED_FLUSHED` 及重开字段；更新 `driverWallets` 待入账按司机分账额计算），新增 `orderSettlements`（权限 `payments.read`，支持日期/城市/公司/搜索筛选与 CSV 导出）。
   - `orders` 每单 `timeline` 使用实际计价里程（`meter.pickupMeters` / `fareDetail.meters`，无实际定位时明确标注预估回退），`feeBreakdown` 展示预估运价、运价费、区域服务费、优惠券抵扣、乘客应付、乘客实付、空车费、累计退款、平台差额费、平台佣金、公司佣金、地图服务费、司机分账入账。
3. **管理动作（`action`）**：
   - `order.cancel`：支持 `responsible: boolean`。
   - `ops.company.save`：兼容旧参数 `{id?, expectedVersion?, name, supportPhone, enabled}`，并支持可选 `{mapServiceFee (分, 0..100000), platformRate (0..100), invoiceTitle, taxNumber}`。
   - `ops.companySplit.open` / `ops.companySplit.rebind`：`{companyId, expectedVersion, accountName, bankName, bankAccount, contactMobile?}`（开户前强校验公司已维护 `taxNumber` 商户信息；生成模拟扫呗虚拟户 `SBVA...`，换绑更新虚拟户号，状态置为 `SIGNED`）。
   - `ops.companySplit.query`：`{companyId}` -> 返回模拟扫呗分账关系查询结果弹窗数据。
   - `ops.companySplit.withdraw`：`{companyId, expectedVersion, amount, note?}` -> 从公司分账可用余额模拟提现至对公账户并记流水。
   - `ops.pointsRule.save`：兼容旧 `{audience, expectedVersion, perOrder, enabled}` 与新 `{audience, expectedVersion, enabled, rules: [{trigger, mode, points, tiers}]}`。
   - 以及 `OpsExtras` 全部动作：`ops.tariff.save`、`ops.serviceFee.save`、`ops.couponTemplate.save`、`ops.couponPool.recharge`、`ops.newUserCoupon.save`、`ops.referralRule.save`、`ops.serviceScoreRule.save`、`ops.invoice.redFlush`、`ops.invoice.reissue`、`ops.invoiceReissue.decide`、`ops.invoiceIssuer.save`、`ops.techInvoice.issue`。
