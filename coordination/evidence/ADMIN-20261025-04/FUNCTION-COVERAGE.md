# 本轮后台功能核对与口径

依据为用户提供的原后台订单中心截图、本地 Java 请求/实体/控制器，以及先前原功能索引。没有找到完整原后台前端工程。本轮未访问原线上后台、原数据库或原密钥。

| 原订单查询条件 | 本轮处理 | 数据依据与限制 |
|---|---|---|
| 订单时间 | 开始/结束日期 | 订单创建日，UTC+8，包含选定首尾两日；缺失或损坏时间不能推断 |
| 订单类型 | 即时、预约、司机报价、议价 | 体验共享订单持久化 kind；不捏造电话叫车/代叫分类 |
| 计费模式 | 明确未实现、禁用且说明 | 共享订单未保存原系统线上/线下 billingMode；费用来源不能当计费模式 |
| 乘客电话 | 乘客账号电话 | 关联持久乘客账户，不是原系统另填的联系人 contactNumber |
| 驾驶员 | 账号及姓名 | 关联持久司机账户；孤立旧记录保留原编号 |
| 驾驶员电话 | 电话筛选 | 原账号手机，不从掩码推断 |
| 订单状态 | 完整当前体验状态 | 包括司机取消后待乘客续叫，不能当作已终止 |
| 取消类型 | 乘客、司机、后台 | 未实现超时/有责分类；不自行判责 |
| 车辆号牌 | 车牌筛选 | 关联司机持久档案 |
| 订单编号 | 编号筛选及详情 | 共用 canonical 订单编号 |
| 行政区划 | 城市筛选 | 体验环境已有城市字典及订单 city |
| 所属公司 | 明确未实现、禁用且说明 | 没有共享订单公司ID；不把演示组织名当公司维度 |
| 是否指派 | 明确未实现、禁用且说明 | 尚无后台指派业务或指派标识；已接单不等于指派 |

九个服务端查询数据集：共享订单、司机与车辆、乘客、模拟账务、评价投诉反馈、操作日志、按日经营、取消记录、模拟退款。schema/options 来自同一服务端；筛选、分页、汇总和全匹配导出共用同一选择过程，导出不只当前页，也不再忽略过滤。输入草稿须点击查询后才应用；导出按已应用条件。

司机列表可按账号、电话、城市、等级、资质、车型及车牌查询；乘客按账号、电话、城市查询。旧账号表没有登记时间，注册日期不可伪造，所以日期条件说明后禁用。模拟账务按订单/提现、支付、退款、提现审核状态、订单及账号；支持按来源、状态、账号、订单和提交日；日志支持操作者、动作及日期，查询全部持久审计，不限旧页最近200条。

经营报表按 UTC+8 订单创建日分组；已完成模拟收款统计已完成且仍已付款订单费用，是订单队列口径，不是银行清算或历史收款净额。退款每个历史轮和当前轮独立记录，等额同刻不去重；按退款实际记录时间筛选。取消记录每条当前取消/待续叫订单一行，不能声称完整历次取消流水。支付、退款、提现分开汇总，禁止相加充当营业额。

保留已有订单详情、报价、行程、原因确认、审计与角色权限。后台 Google IAP 入口及管理会话均保留。真实银行清分、分账、税务发票、真实短信和其他外部配置缺口不以模拟页面伪装接通；本轮没有新增这些外部接口。是否指派、公司归属与正式计费模式需要后续统一业务模型及原规则依据，当前不能标记全量原系统已复刻。

本轮测试分为：185后端回归（含18新增查询边界）、9签名IAP/会话/查询/导出测试、独立浏览器实际筛选/导出/权限/失败恢复，及发布后的体验环境读回。具体通过范围、失败修复和未执行项以最终测试与发布报告为准。
