## 1. 分账公式：差额费重复扣减

原文45–70行。令运价F、服务费S、券实际抵扣C、实付P=F+S−C、地图费M；运价两项手续费合计fF，实付两项手续费合计fP，差额Δ=fP−fF；可抽佣A=S−Δ。这里把62行未定义的“平台承担差额手续费”暂按57行“平台承担差额费”理解，把平台/公司比例之和暂设为1；**都是用于寻找反例的假设，未被当作正式规则**。

文档的司机D=F−fF−M，公司K=A×公司比例，平台L=M+A×平台比例−Δ。因此：

```
L+K−M = A−Δ                    （不等于文档67行的A）
扫呗可分金额B = P−fP+C = F+S−fP
D+K+L = F+S−fF−2Δ = B−Δ        （不等于文档68行的B）
末条恒等式右侧 = D+K+L+Δ+fF = F+S−Δ
```

## 3. 公司开户签约与证件门禁

公司资料/商户/分账关系/司机companyId目前不存在权威模型，仅有草稿catalog。公司状态建议区分DRAFT→SUBMITTED→PENDING→VERIFIED_ACTIVE，以及REJECTED/SUSPENDED/CLOSED/UNKNOWN；绑卡成功、提交成功、按钮查询完成都不等于签约已生效。更换账户先保存候选与关系版本，核验成功后再原子切换；历史单固定原company/account版本，失败不覆盖仍有效旧账户。

证件现状：`domain.py:94` 在新接单校验资质及有效期，validUntil包含当日，旧缺失/不可解析日期未建立到期事实；`:217` 上线本身目前不做证件有效期校验。`:299` 已通过证件仅到期前30天允许更新，提交即转PENDING；`:155` 全部审核通过才恢复APP资质状态。与文档“提前60天提醒、更新后不再限制”的含义不完全相同。

## 4. 优惠券资金池：状态及不变量

原文178–200行可提炼，但尚不能直接执行：

- 资金池只接已核实充值回执：总充值T增加、可用A增加。领取成功时按券占用R把A转冻结H；必须同一事务检查余额及熔断，竞争领取不能负余额。充值去重键需商户+入账单号，模拟充值与真实回执隔离。
- 券状态建议AVAILABLE（已领取且资金冻结）→RESERVED(orderId)（订单占用）→REDEEMED（满足完成且资金入账条件后核销）或退回AVAILABLE；已过期且无订单占用则EXPIRED并释放资金。**订单占用≠资金核销**，不应共用“已使用”一字段。
- 订单占用后跨有效期保持冻结，不能过期任务直接解冻；取消后有效券退回并继续冻结，失效券进入EXPIRED再解冻；同一事务处理退券/到期，避免先释放又重复释放。同券只能被一个有效订单占用。
- 实际优惠U低于占用R时，核销U并释放R−U；原文未明确R按券面额还是实际最大成本。取消返券并不自动意味着释放整笔资金，须结合券是否仍有效。
- 暂无提现/退款/调整时不变量T=A+H+已核销U，A/H/U≥0；核销并非订单支付，必须绑定补贴账与供应商回执。已核销后订单退款要冲正并确定返券/返资金方式，不应编辑旧金额。充值退款或平台调账引入后须单列科目更新恒等式。
- 原文同时提“已完成”及“达到入账条件”；本系统DONE可能与资金事件不同步，触发条件要使用明确的双条件/权威事件。零实付或部分退款同样不能凭stage假定补贴已经完成。
- 5000/500阈值原文未写单位；若为元，分别是500000/50000分。低于500同时满足两种告警：需明确只发最高等级还是两种各一次；“单日一次”建议pool+等级+UTC+8日期唯一键，消警回落阈值和跨日重发需确定。余额扣减前即检查，不能靠群消息送达后才熔断；恢复应来自已核实余额，通知失败不改变资金状态。
