# 参考与实现边界
用户直接要求：有效地点点选即确认，不再使用此地点；途经点入口置目的地页；修历史无反馈；两端界面更美观、操作更少。
基线是本项目22版原生代码/真实截图，普通既有应用实现，不新建Sites原型。参考官方来源：
- DiDi Help https://web.didiglobal.com/au/help-center/ ：Where to目的地输入旁的+入口添加途经点；不同地区规则不能照搬。
- Uber https://www.uber.com/us/en/ride/how-it-works/multiple-stops/ ：Where to旁+添加途经点。仅借鉴入口，不将其5点/真实计费规则引入；本项目保持2途经点和既有业务。
- Uber Base https://base.uber.com/6d2425e9f/p/6d2425e9f ：统一基础/组件/模式框架；该页具体视觉细节不可读，不假装看过当前App所有屏幕。
root看22版f01真实截图：多重大圆角带边框、浅绿按钮/渐变阴影抢层级，地址区域拥挤，主要任务不突出。方向：白/近白底，墨色主文字，品牌青绿克制点缀；单一强CTA，轻分隔线/少嵌套卡，起终点线性结构，行程方式紧凑分段。保留危险色/禁用态/大字适配，不隐藏模拟能力说明。
选址一击确认只确认地址，不自动下单/付款/取消或保存无关设置；缺坐标历史项必须明确反馈搜索/解析，不能0/NaN/瞎猜坐标。保持地图在上、查询初始空、模糊结果在下。取消未选不改，已明确点选即本地草稿确认。
