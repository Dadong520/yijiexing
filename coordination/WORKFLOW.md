# 宜捷行长期协作机制

用户2026-10-25授权：协调者领导两个Codex会话和反重力，按前端、后端、测试部署分工。开发尽量交反重力，Codex聚焦契约、疑难问题及独立验收。不创建常驻AI循环。

## 日常运行

1. 用户把需求给协调者。协调者只拆本轮必要任务，写任务编号、负责人、允许路径、验收条件和时间边界；没有任务的会话保持idle。
2. 执行者先读根AGENTS、STATE、BOARD、本任务及本角色handoff。启动回复一条简短ACK并写入交接卡，不再重复转述全部历史。
3. 反重力默认承担小程序/后台页面、常规前端修复和自测；frontend会话承担司机原生端与前端集成复核；backend承担服务端数据、接口契约、金额状态和幂等设计。协调者按具体任务变更归属，不能跨任务抢写。
4. 作者自测后推送任务分支，提交短交接及证据；必须给完整SHA。不同会话对关键差异与业务场景验收。失败记录具体场景并退回原作者，不让多人同时修同一文件。
5. 协调者确认独立PASS匹配业务源提交SHA，再合并；需要发布的任务由唯一deploy_owner执行。已获体验环境发布授权，不逐次问用户；仍需部署后回读版本、健康、权限与业务结果并保留回退。

## 防止上下文膨胀

- STATE只保留当前事实与指向；BOARD只保留活跃任务；每个角色只写自己的交接；旧完成任务移入archive，不累加到入口规则。
- 每阶段完成、约40分钟有效工作、等待或结束本轮前保存交接。卡片最多6KB，任务8KB，STATE8KB；自动检查超限就失败。
- 工具只读取相关文件、变化和短日志尾部；大截图/日志进evidence，不重复贴进聊天。未变化测试不重复全跑，变更后才复测相关范围。
- 自动压缩后从文件恢复。没有可靠上下文百分比就不编造阈值；出现重复分析、忘记已定结论时立即落盘重建短工作上下文。
- 不能承诺自动清空已有桌面会话。需要真正新开主会话时提供“读取AGENTS+STATE+任务ID+角色卡”的短交接入口，由用户明确创建/新开；不复制整段旧聊天。

## 验收与证据

- 结果只能PASS、FAIL、BLOCKED或NOT_RUN；“提交成功”“50项通过”“返回302”分别只证明各自事实，不等于新功能、完整登录或三端验收。
- 券、积分、费用与资金记录必须由共享后端持久化、按账户隔离、绑定订单并幂等。客户端演示不可冒充到账。预付与完单不是同一事件。
- 录音、地图、实名认证、公安背景审查等未实现能力不得在产品中显示已开启/已通过。真实资质展示必须有API数据依据。
- 本轮AG原始提交已独立审查FAIL；修复后另验精确新SHA。没有微信AppID时，微信编译/真机/地图插件仍记NOT_RUN，不用H5预览冒充。
- 发布前执行 `python3 tools/check_coordination.py --release-task <任务ID> --sha <完整业务源SHA>`。要求作者之外的验收者、匹配SHA的实跑命令/退出码、存在且哈希一致的证据文件，以及releaseReady=true。仅开发源码通过但正式发布条件未满足时保持releaseReady=false，不把合并当真机发布。

## 自动化与限制

GitHub Actions的project-gate执行记录结构检查及小程序回归，旧运行会被同分支新运行取消；不调用AI、不部署、不保活。它是廉价回归，不是独立业务验收。

当前GitHub私库套餐的分支保护API返回403，要求Pro或公开仓库。保留私库、不升级；不声称已配置服务器强制保护。CLI与操作权限由已授权用户持有，流程依赖角色遵守与协调者统一发布，不能保证任何有权限的人都无法绕过。

## 恢复入口

“你参与宜捷行项目，角色为<role>，任务为<task-id>。先读取本仓库AGENTS.md、coordination/STATE.md、BOARD.json、该任务和本角色handoff；核对Git状态与远端SHA，按allow_paths继续。先报告三行：基线、当前阻塞、下一动作，不重新扫描全部项目。”

## 单一指令入口与Gemini优先（用户2026-10-25追加授权）

用户默认只在coordinator会话提需求、问进度或询问Gemini意见。协调者可以直接给两个Codex会话及Gemini/反重力派任务、询问和追修，再向用户汇总；用户无需自行转发。只有账号登录、验证、业务决策或必须用户亲自完成的操作才请求用户介入。

默认让Gemini承担主要实现与常规测试/报告；Codex聚焦任务拆解、接口与关键规则、疑难问题和独立验收。职责由任务allow_paths约束，不能为增加Gemini工作量而让多个执行者争写共享后端。Gemini也可承接明确后端实现任务，但须先定契约，backend审查，coordinator统一合并部署。

优先用反重力agy CLI，沿用用户可用模型gemini-3.8-flash-high，不改全局设置，不默认改用另一个Gemini CLI或额外API付费。每任务新执行上下文，只传规则入口、任务ID、基线、允许路径、验收和时限；执行结束收JSON结果、完整SHA和证据。续跑只指定本任务conversation_id，禁止latest/continue误入别的任务或同桌面会话并发。

上下文压缩由各产品自身管理，协调者不宣称能读取或统一设定所有工具阈值。项目文件是可靠恢复入口；每阶段/约40分钟有效工作保存短交接，再由协调者按需新开执行上下文。没有任务时不启动模型，不做常驻空轮询；当前回合结束不意味着持续后台工作。

CLI验证和调用约束见coordination/GEMINI_CLI.md。当前已实测非交互调用返回CLI_READY；该测试仅证明本机CLI连通，不代表所有编辑、权限、构建和部署自动通过。

## 记忆、预警与接任（2026-10-26-v3，替代旧恢复入口）

遵守START_HERE、MEMORY_POLICY、SESSION_REGISTRY、DECISIONS。中央目录保存最新运行状态，Git工作树保留可提交检查点；旧快照不得反向覆盖中央。每角色阶段/约40分钟有效工作更新短卡，未知上下文占用写UNKNOWN。具体预警与换会话条件以MEMORY_POLICY为准，百分比门槛是项目预防约定，不是产品限制。

下一次大任务前若角色已HANDOFF_RECOMMENDED，coordinator先向用户提示并给NEW_CHAT_PROMPT；达到HANDOFF_REQUIRED则只做消除冲突和交接。用户新开或明确要求创建后才切换，SESSION登记唯一协调者，旧对话停止新派单。角色接单/恢复执行check_coordination.py --memory-role，提交/CI运行结构及记忆检查器回归；无任务不监控、不唤醒模型。
