## 一、 独立 UI 执行过程与真实失败证据

在根据指令独立执行无终点即时订单用例的过程中，严格按照真实 UI 节点进行操作与断言，保留的原始执行与失败证据记录如下：

### 1. 首轮执行：发单按钮文本不匹配中断
- **执行现象**：脚本在完成无终点选项寻找后，向下滚动查找发单候选词（`立即叫车`、`呼叫即时用车`、`确认叫车`），因匹配不到按钮触发 `AssertionError: 失败: 未找到发单按钮！` 严格中断。
- **原始证据**：
  - 保存现场截图与 XML：`fail_call_btn_not_found.png` / `fail_call_btn_not_found.xml`。
  - XML 现场查验显示实际 Compose 渲染按钮文本为：`确认呼叫 · 即时用车`（位于 `bounds="[380,1435][700,1488]"`），与原假定候选文案存在间隔号及字面差异。

### 2. 第二轮执行：复选框误切与带终点订单误建
- **执行现象**：
  - 脚本将发单按钮修正为 `确认呼叫 · 即时用车` 后重跑；
  - 在第 2 步处理“先叫车，稍后补充目的地”时，脚本点击了文本节点 `先叫车，稍后补充目的地`（`android.widget.TextView`，`clickable="false"`），由于该文本不可点击且未绑定同行左侧 `android.widget.CheckBox`，复选框由已选误切到未选（`checked="false"`）；
  - 随后点击 `确认呼叫 · 即时用车`，实际在云端创建了**带有默认终点（夷陵广场）的标准即时订单**，真实订单号为：**`PORDcecfc8298776`**（费用为体验估价 `¥29.26`）；
  - 脚本在进入订单详情页后，严格执行断言：要求必须同时包含“目的地待补充”且费用不能为估价值，因断言失败抛出 `AssertionError: 失败: 订单 PORDcecfc8298776 界面未包含'目的地待补充'标签！`，并在现场严格中断。
- **原始证据**：
  - 现场布局保存为：`fail_no_dest_pending_label.png` 与 `03_order_detail_created.png`。
  - 详情页真实抓取文本：`['等待司机接单 / 报价', '即时用车 · PORDcecfc8298776', '行程路线', '出发 宜昌东站 · 出租车上客区', '到达 夷陵广场 · 东侧入口', '费用明细', '体验估价', '¥29.26']`。

### 3. 现场清理与现场状态
- **现场清理**：为避免在两端遗留悬挂活动单，执行自动化指令滚动找到“取消本次订单”，在取消弹窗点击“确认提交”，将订单 `PORDcecfc8298776` 状态成功流转为“已取消”（`10-23 22:37 · 乘客已取消订单`），随后退回首页。
- **当前状态**：乘客端当前显示“暂无进行中订单”，司机端处于听单首页，两账号均无未结订单。
